# 开发规划

本文区分已完成能力和候选规划。后续范围可调整，未完成项目不代表当前系统已经提供相应功能。

## v1.0 Diary MVP（已完成）

- 创建、读取和更新当日科研日志。
- 日志字段：完成事项、遇到问题、下一步计划。
- 同一天重复保存时更新原记录。
- 历史日志按日期倒序展示。
- 日志详情页面。
- 对三个主要日志字段进行关键词包含搜索。
- Prisma + SQLite 数据持久化。
- Diary 集成测试、ESLint 和生产构建验证。

## v2.0 多人版本（已完成）

- 使用 Better Auth 实现邮箱密码注册和登录。
- 支持退出、Session 持久化和获取当前用户。
- 新增 `/login`、`/register` 及登录状态导航。
- `User` 与 `Diary` 建立一对多关系。
- Diary 唯一约束从 `date` 调整为 `(userId, date)`。
- 今日、历史、搜索和详情均基于 Session 用户隔离。
- 他人 Diary 详情返回 404。
- 保留并迁移单用户时期的已有 Diary 数据。
- 双用户认证与数据隔离测试。

## v2.1 用户体验优化（进行中）

### 已完成

- 用户时区字段，默认 `Asia/Shanghai`。
- 基于用户时区计算“今天”。
- 服务端时区合法性校验。
- 上海与东京日期边界测试。
- 用户个人设置页面，可修改用户名和时区，邮箱只读。
- 登录后的基础 Dashboard：今日状态、最近 3 篇日志和快捷入口。

### 尚未实现的候选内容

- 登录与注册流程体验优化。
- 历史、搜索等页面的空状态优化。

保持 MVP 简洁：上述候选项应分阶段实现，不在单次迭代中引入复杂的资料系统、通知系统或分析平台。

## 后续基础设施规划（未实现）

### PostgreSQL 与云端部署

- 设计 SQLite 到 PostgreSQL 的可验证迁移方案。
- 在测试环境演练 Schema 和数据迁移。
- 对迁移前后的用户、Diary 数量、ID 和内容进行一致性校验。
- 配置生产环境数据库连接、Better Auth 密钥和应用基础 URL。
- 建立备份、恢复和部署回滚流程。
- 验证多实例部署下的 Session 和并发写入行为。

### 可观测性与质量

- 根据部署需要补充错误监控和结构化日志。
- 保持认证、数据隔离、日期边界、lint 和 build 为发布前检查项。
- 数据库切换后增加 PostgreSQL 环境的集成测试。

## AI 方向（长期候选，未实现）

AI 功能应建立在稳定的数据权限和云端基础设施之上，并继续遵守用户隔离。候选方向包括：

- 对用户自己的阶段日志生成总结。
- 从历史记录中提炼进展、阻塞和下一步计划。
- 在用户自己的 Diary 范围内提供语义检索或问答。

在实施前需要先确定模型供应商、成本、隐私边界、数据保留策略和明确的用户触发方式。AI 不应替代原始 Diary，生成结果也不应跨用户使用数据。

## 每阶段交付标准

- 数据库变化必须通过 Prisma 迁移管理。
- 功能改动应增加或更新相关测试。
- 运行相关集成测试、`pnpm lint` 和 `pnpm build`。
- 数据隔离能力必须使用至少两个用户验证。
- 每次改动创建独立 Git commit，便于追踪和回滚。
